# Policy Navigator Edge Functions — API Contract

Generated by task 2-21b. Documents the **actual** request and response shapes for every
implemented Edge Function, derived from reading the source code.

> **Not yet documented:** `acknowledge-alert` and `admin-alerts` are scaffolded but not yet
> implemented (tasks 2-22 and 2-23). They will be added to this document when those tasks
> complete.

All responses use the shared `SuccessEnvelope<T>` / `ErrorEnvelope` shape from
`_shared/response.ts`:

```
SuccessEnvelope<T>  →  { ok: true;  data: T }
ErrorEnvelope       →  { ok: false; error: { code: ErrorCode; message: string } }
```

Named error codes and their default HTTP status:

| `ErrorCode`       | Default status |
|-------------------|----------------|
| `RATE_LIMITED`    | 429            |
| `OLLAMA_EXHAUSTED`| 503            |
| `INGESTION_FAILED`| 500            |
| `NOT_FOUND`       | 404            |
| `UNAUTHORIZED`    | 401            |

## query-pipeline

**Method:** POST  
**Auth:** Supabase JWT — caller must include `Authorization: Bearer <anon-key-or-user-session-jwt>`. The function itself performs no explicit JWT check; Supabase Edge Function runtime enforces it by default.  
**Path:** `/functions/v1/query-pipeline`

Implements the RAG query pipeline (tasks 2-7 through 2-13). As of task 2-21b, tasks 2-7
(rate limiting, embedding, parallel BM25+vector retrieval, RRF merge, ancestor enrichment) is
complete. Tasks 2-8 through 2-13 (reranking, LLM generation, citation assembly) are not yet
implemented — see **Response — In-progress (normal retrieval path)** below.

### Request

```json
{
  "query": "string (required, non-empty)"
}
```

The optional `context` field defined in `QueryRequest` is accepted by the type but not read by
the handler.

### Response — Success: incomplete search (200)

Returned when the maximum RRF score across all retrieved candidates falls below the
`INCOMPLETE_SEARCH_FLOOR` threshold (default `0.005`, tunable via env var). Shape is the full
`QueryResponseData` envelope with an empty answer.

```json
{
  "ok": true,
  "data": {
    "answer": "",
    "citations": [],
    "chunkText": {},
    "temporalFlag": false,
    "amendmentCaveat": null,
    "pendingChangeNotice": null,
    "incompleteSearchWarning": true,
    "freshnessTimestamp": null
  }
}
```

### Response — In-progress: normal retrieval path (200)

Returned when retrieval succeeds and at least one candidate meets the floor threshold.
**This response shape is temporary** — tasks 2-8 through 2-13 will replace it with the full
`QueryResponseData` shape (same as the incomplete-search response but with `answer`, `citations`,
`chunkText`, and all flag fields populated).

```json
{
  "ok": true,
  "data": {
    "candidates": [
      {
        "key": "ordinance_provisions:uuid",
        "table": "ordinance_provisions | vote_tallies | policy_decisions | budget_indicators | narrative_chunks",
        "id": "uuid",
        "row": { "...": "raw DB row fields" },
        "rankBm25": 1,
        "rankVector": 3,
        "rrfScore": 0.0312,
        "ancestors": [
          {
            "municode_node_id": "uuid",
            "title": "Chapter 2 — Administration",
            "node_depth": 2
          }
        ]
      }
    ],
    "total": 42
  }
}
```

`ancestors` is populated only for `ordinance_provisions` candidates; it is an empty array for
all other chunk tables. Candidates are ordered by `rrfScore` descending. The response includes
at most 8 candidates.

### Final Response — Full pipeline (200)

Shape returned once tasks 2-8 through 2-13 are implemented:

```json
{
  "ok": true,
  "data": {
    "answer": "string — generated answer text",
    "citations": [
      {
        "chunk_id": "uuid",
        "source_url": "https://...",
        "source_title": "string",
        "page_number": 12,
        "rank": 1
      }
    ],
    "chunkText": {
      "<chunk_id>": "full text of the cited chunk"
    },
    "temporalFlag": false,
    "amendmentCaveat": "string or null",
    "pendingChangeNotice": "string or null",
    "incompleteSearchWarning": false,
    "freshnessTimestamp": "2026-06-01T00:00:00.000Z"
  }
}
```

`chunkText` is keyed by `chunk_id` (matching `citations[].chunk_id`).  
`freshnessTimestamp` is `null` when no source timestamp is available.

### Response — Errors

| Status | `errorCode`       | Condition |
|--------|-------------------|-----------|
| 405    | `NOT_FOUND`       | Method is not POST |
| 400    | `NOT_FOUND`       | `query` field missing or empty |
| 400    | `NOT_FOUND`       | Request body is not valid JSON |
| 429    | `RATE_LIMITED`    | IP exceeded rate limit window (default 10 req/min) |
| 503    | `INGESTION_FAILED`| Rate-limit bucket write failed (transient DB error) |
| 500    | `INGESTION_FAILED`| Supabase AI Session embedding call failed |

## ingest-orchestrator

**Method:** POST  
**Auth:** `Authorization: Bearer <service_role_key>` — called exclusively by pg_cron via
`private.cron_invoke_edge_function`, which reads the service role key from Supabase Vault at
runtime. Not intended for direct external calls.  
**Path:** `/functions/v1/ingest-orchestrator`

### Request

```json
{
  "pending_ingestion_id": "uuid (required)"
}
```

### Response — Success (200)

Four distinct success shapes depending on what happened:

**Row not in `pending` status** (already processing, done, failed, or not found):
```json
{ "ok": true, "data": { "skipped": true, "reason": "not_pending" } }
```

**AI Session unavailable** (deferred without consuming a retry attempt):
```json
{ "ok": true, "data": { "status": "deferred", "reason": "ai_session_unavailable" } }
```

**Duplicate PDF content** (same `content_hash` already in `documents` as `current`):
```json
{ "ok": true, "data": { "status": "skipped", "document_id": "uuid" } }
```

**PDF ingestion complete** (`doc_type` is `bos_minutes`, `bos_summary`, or `budget_pdf`):
```json
{ "ok": true, "data": { "status": "done", "document_id": "uuid", "chunk_count": 47 } }
```

**Municode ingestion complete** (`doc_type` is `municode_api`):
```json
{ "ok": true, "data": { "status": "done", "document_id": "uuid", "provision_count": 123 } }
```

### Response — Errors

| Status | `errorCode`       | Condition |
|--------|-------------------|-----------|
| 400    | `INGESTION_FAILED`| `pending_ingestion_id` missing from body |
| 400    | `INGESTION_FAILED`| Request body is not valid JSON |
| 500    | `INGESTION_FAILED`| DB lookup for `pending_ingestions` row failed |
| 500    | `INGESTION_FAILED`| Failed to claim processing slot (status → `processing`) |
| 500    | `INGESTION_FAILED`| Ingestion attempt failed — will retry (attempts < 3, reset to `pending`) |
| 500    | `INGESTION_FAILED`| Max attempts reached (3 failures; status set to `failed`) |

On transient failures (attempts < 3) the ingestion row is reset to `status = 'pending'` so
pg_cron will retry using exponential backoff (1 min → 5 min → 30 min). A `pending_alerts` row
is written for every failure regardless of retry outcome.

## keepalive-health

**Method:** Any (handler ignores the method; only one route exists)  
**Auth:** Public — permanently excluded from the task 3-7 pre-launch auth lockdown. Intended
as the target for GitHub Actions keep-alive pings.  
**Path:** `/functions/v1/keepalive-health`

### Request

No body required.

### Response — Success (200)

```json
{
  "ok": true,
  "data": {
    "alive": true,
    "ts": "2026-06-23T12:34:56.789Z"
  }
}
```

`ts` is the ISO 8601 UTC timestamp at the moment the DB ping succeeded.

### Response — Errors

| Status | `errorCode`       | Condition |
|--------|-------------------|-----------|
| 500    | `INGESTION_FAILED`| Supabase DB `ping()` RPC call failed |
